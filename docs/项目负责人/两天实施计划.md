# 两天实施计划

## 成功定义

两天结束时，必须能展示：一个真实 iOS 功能、对应 Web 实现、自动测试结果和差异说明。只有文档、配置或脚本不算成功。

## 第一天：理解并选择

| 时间盒 | 工作 | 产物 | 停止条件 |
| --- | --- | --- | --- |
| 1 小时 | 配置源项目并记录 commit | `.runs/<run-id>/source.json` | 输入不干净或项目不存在 |
| 2 小时 | 构建、安装和启动 iOS App | 构建日志、启动截图 | 两轮修复仍不能启动 |
| 2 小时 | codebase-memory 分析项目 | 模块、入口、主要关系 | 索引不可用且无替代证据 |
| 2 小时 | Claude 整理简明蓝图 | `源项目蓝图.md` | 蓝图无法支持功能选择 |
| 30 分钟 | 用户选择一个功能 | 蓝图中的范围决定 | 用户尚未确认 |

## 第二天：实现并验证

| 时间盒 | 工作 | 产物 | 停止条件 |
| --- | --- | --- | --- |
| 1 小时 | 深入分析选中功能 | 源码、调用链、行为和依赖 | 功能范围过大，需缩小 |
| 1 小时 | Spec Kit 制订最小计划 | `Web迁移计划.md` | 任务超过 10 项，需简化 |
| 3 小时 | Claude 实现 React 功能 | `webapp/` | 两轮修复仍无法运行 |
| 1 小时 | Playwright 验证 | 报告、截图、trace | 核心路径失败 |
| 1 小时 | 整理结果并验收 | `最终验收报告.md` | 用户决定继续、调整或停止 |

## Claude 执行顺序

1. 读取 `docs/00-authority.md`、本计划和 `.planning/HANDOFF.md`；
2. 使用 planning-with-files 更新任务状态；
3. 每完成一个时间盒，更新 `项目总览.md`；
4. 所有事实必须链接到代码、日志、截图或测试；
5. 遇到两轮仍未解决的问题，停止并更新 handoff；
6. 未经用户选择功能，不得创建 WebApp；
7. 不得额外建设 Runner、Gate、Schema、Analyzer 或 Agent 平台。

## 两天结束时的判定

| 判定 | 条件 |
| --- | --- |
| `CONTINUE` | 一个真实功能迁移成功，方法明显可复用 |
| `ADJUST` | 闭环基本成功，但工具或步骤需要替换 |
| `STOP` | 无法产出真实功能，成本明显高于价值 |
