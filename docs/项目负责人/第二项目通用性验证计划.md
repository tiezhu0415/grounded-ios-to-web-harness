## 2. 前置条件

在开始前，第二项目必须满足以下条件：

1. **真实可运行的 iOS 项目**：Xcode 工程可在本地 `xcodebuild` 构建并在 iOS Simulator 启动。
2. **可本地审计**：提供完整源码或压缩包，允许在 `xcode/` 下建立本地 Git 身份。
3. **至少一个可被 Web 替代的功能**：不涉及支付、推送、相机、健康数据等强原生能力。
4. **数据可本地化**：功能所需数据可以从源码中提取为静态 JSON/TypeScript，或可通过 mock 提供。
5. **无强外部依赖**：优先选择不依赖 Firebase Auth / Firestore / 私有后端账号的功能。

## 3. 执行步骤

复用第一项目的 Harness 流程，但避免假设具体框架：

### Phase 0 — 输入与身份
- [ ] 将第二项目复制到 `xcode/<second-project>/`
- [ ] 初始化本地 Git repo，记录初始 commit
- [ ] 更新 `harness.yaml` 中的源项目路径和 scheme
- [ ] 排除 `GoogleService-Info.plist`、密钥、`xcuserdata/` 等

### Phase 1 — 跑通源 App
- [ ] `xcodebuild build` 成功
- [ ] `simctl launch` 启动成功
- [ ] 保存启动截图到 `.runs/<date>/`

### Phase 2 — 生成蓝图
- [ ] 使用 `codebase-memory-mcp` 索引项目
- [ ] 输出 `docs/项目负责人/源项目蓝图.md`（或第二项目对应文档）
- [ ] 列出功能清单、模块边界、依赖关系

### Phase 3 — 选择功能
- [ ] 用户预先授权或 Claude 推荐 1～2 个最小功能
- [ ] 选择标准：可在 1～2 天内迁移、可被 Playwright 验证、不依赖强原生/后端
- [ ] 记录排除项（登录、支付、搜索、详情等）

### Phase 4 — 制订 Web 迁移计划
- [ ] 分析入口 View、ViewModel、Model、数据流
- [ ] 输出迁移任务清单（类似 `Web迁移计划.md`）
- [ ] 确定数据本地化方案（从 Swift 提取为 TS/JSON）

### Phase 5 — 实现 WebApp
- [ ] 在 `webapp/` 或新目录实现 React + TypeScript 版本
- [ ] 保持手机优先布局（最大 430px）
- [ ] 使用真实数据，移除超出范围的功能

### Phase 6 — 自动验证
- [ ] `npm run build` 成功
- [ ] `npx playwright test` 全部通过（目标 ≥5 个核心用例）
- [ ] 保存截图、报告、trace

### Phase 7 — iOS 运行验证
- [ ] 登录/导航到目标功能（如有登录，使用 DEBUG 预填或手动点击）
- [ ] 截图验证源功能行为
- [ ] 与 Web 结果对照

### Phase 8 — 决策
- [ ] 更新 `最终验收报告.md`
- [ ] 用户决定 CONTINUE / ADJUST / STOP

## 5. 风险与观察点

| 风险 | 应对 |
| --- | --- |
| 第二项目使用 SwiftUI/UIKit 混合或复杂架构 | 不预设框架，只关注数据流和 View 边界 |
| 数据来自 Firestore/私有 API | 优先选择本地数据可替代的功能；否则评估 mock 成本 |
| 登录是功能前置条件 | 使用 DEBUG 预填或临时自动登录，只验证登录后的目标功能 |
| 项目过大，索引超时 | 使用 `moderate` 或 `fast` 索引模式，先扫描关键目录 |
| UI 自动化点击坐标失效 | 记录本次 cliclick 坐标推导方法；第二项目需重新校准 |
