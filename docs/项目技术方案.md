# iOS→Web Harness 技术方案

## 目标

把整个 iOS App 迁移为一个有统一手机尺寸、完整导航、连续交互和可验证覆盖的 WebApp。用户只在开始时指定范围，结束时验收。

## 核心流程

```text
iOS 源码、导航和 Assets
          ↓
自动生成全项目页面覆盖清单
          ↓
先建手机 App Shell、全局导航、全部路由
          ↓
Claude/Codex 按清单连续实现整个 App
          ↓
Playwright 验证页面、按钮和关键流程
          ↓
关键状态使用 Pixelmatch + SSIM 辅助精修
          ↓
用户打开一个 WebApp 链接验收
```

## 两种工作模式

| 模式 | 命令 | 用途 | 能否代表整项目完成 |
| --- | --- | --- | --- |
| 全项目 | `./harness prepare --project <id>` | 生成全部 iOS View 覆盖清单，驱动整体迁移 | 最终 `check --mode app` 通过后才可以 |
| 单功能 | `./harness capture --project <id> --feature <id>` | 分析、截图、视觉对比和局部精修 | 不可以 |

## 全项目完成条件

1. 自动扫描到的每个源页面都有 Web 实现、路由和行为测试；
2. 子组件自动列为分析参考，不要求 AI 逐项填表；
3. 存在统一手机容器，桌面打开时不会铺满屏幕；
4. 原生全局导航可以连接所有顶层模块；
5. build、lint 和真实 Playwright 测试通过；
6. 未实现、排除或依赖外部服务的源页面都会保持项目未完成，不能被文档掩盖。

## 视觉还原

- codebase-memory、SwiftUI/UIKit 源码和 Assets 决定布局、内容、资源与交互；
- iOS 运行截图确认动态状态，并与 Web 使用相同数据和画布；
- Pixelmatch 标出主要像素差异，SSIM 辅助观察整体结构；
- 同一问题最多精修两轮；视觉数字不能替代功能覆盖和完整流程。

## 工具

| 工具 | 作用 |
| --- | --- |
| codebase-memory-mcp | 查找页面、子组件、调用、数据和导航关系 |
| Xcode / Simulator | 运行源 App，确认真实状态 |
| React + TypeScript | WebApp 实现 |
| Playwright | 行为流程、手机容器和导航验证 |
| Pixelmatch + SSIM + Pillow | 关键页面视觉差异与精修证据 |
| Harness | 生成源码覆盖清单并统一执行最终检查 |

## 文件

```text
xcode/<project-id>/                 iOS 源项目
webapps/<project-id>/               一个源 App 对应一个 WebApp
docs/项目/<project-id>/项目蓝图.md  用户和 AI 共用的功能蓝图
.runs/<project-id>/<run-id>/        覆盖清单和必要证据
```

不再建设 G0～G8、审批记录、复杂恢复、通用 Runner 或额外治理文档。
