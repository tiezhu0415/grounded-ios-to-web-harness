# iOS→Web Harness 技术方案

## 目标

让 Claude 主导把任意 iOS App 迁移成一个完整、可操作、手机尺寸的 WebApp；Harness 只在第一版完成后检查遗漏、核心行为和代表页面视觉。

## 总体流程

```text
iOS 源码、Assets、导航关系
            ↓
Claude 自主实现完整 WebApp
            ↓
页面覆盖对账：有没有漏
            ↓
核心行为旅程：能不能真实操作
            ↓
代表页面视觉精修：像不像
            ↓
用户打开一个链接验收
```

## 谁做什么

| 组件 | 只负责什么 |
| --- | --- |
| Claude | 理解 App，自主决定 React 架构、组件、状态、CSS 和实现顺序，完成连贯 WebApp |
| codebase-memory | 从入口追踪页面、导航、依赖和源码关系，帮助检查是否漏页 |
| Harness | 保存覆盖清单、核心旅程和代表视觉证据；执行完成条件 |
| Playwright | 点击、输入、跳转并断言操作结果；截图本身不算行为测试 |
| Maestro | 为核心状态和代表页面建立真实 iOS 运行证据 |
| Pixelmatch + SSIM | 定位代表页面的视觉结构差异，不代表功能完整性 |
| 用户 | 开始时指定范围，结束时打开链接决定是否继续 |

## 三项验收

### 1. 页面覆盖

`项目覆盖.json` 对比：

- iOS 源码页面；
- codebase-memory 导航目标；
- Web 页面和路由。

页面怎么实现由 Claude 决定；页面有没有遗漏由 Harness 对账。每个页面至少有可打开路由和到达测试。

### 2. 核心行为

`behavior-journeys.json` 只记录少量真实用户旅程，例如：

```text
打开列表 → 进入详情 → 改变选项 → 加入集合 → 在另一页面看到结果
```

每项必须包含真实 Playwright 操作和可观察断言。多页面 App 至少一个旅程要跨路由。只打开页面、查找隐藏文字或截图不能通过。

### 3. 代表视觉

第一版功能可用后，从 App Shell 和重要页面中选择至少三个代表页面，用 Maestro 与 Playwright 建立相同状态，再运行 Pixelmatch + SSIM。视觉只负责精修，不再要求每个页面都先截图。

## 防止假完成

以下情况不能返回 `APP_COMPLETE`：

- 把 iOS 运行截图复制成 Web 页面、背景或遮罩；
- 用 `opacity: 0` 等不可见 DOM 文案冒充功能；
- 测试只有 `goto`、文字查找或截图，没有操作后的结果断言；
- 页面清单与 Web 路由对不上；
- 没有跨页面核心旅程；
- 没有代表页面视觉证据；
- 没有最终验证链接。

iOS 项目原有 Assets、字体和图标可以直接复用。外部服务不可用时允许使用明确的 DEBUG fixture/mock，但不能伪造联网成功。

## 时间和停止规则

1. Claude 先完成第一版，不在编码前等待所有截图和检查。
2. Harness 输出明确缺口，Claude修复一次。
3. 行为或视觉仍失败时再精修一次。
4. 两轮后强制停止，向用户报告剩余差异。
5. 不自动调用 Codex；只有用户明确要求才独立审查。

## 完成条件

`./harness check --mode app` 只有同时满足以下条件才返回 `APP_COMPLETE`：

1. 所有源页面已有 Web 实现、路由和到达测试；
2. 源码与 codebase-memory 导航结果对账通过；
3. build、lint、Playwright 和手机外壳通过；
4. Web 实现真实性检查通过；
5. 核心行为旅程通过；
6. 代表页面视觉检查通过；
7. WebApp 查看清单提供可打开链接。

本项目不再建设 G0～G8、审批系统、自动 Codex 循环或通用 Agent 平台。
