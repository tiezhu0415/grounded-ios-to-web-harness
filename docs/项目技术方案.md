# iOS→Web Harness 技术方案（轻量版）

## 目标

Claude 主导实现；Harness 固定“原 App 有什么”和“结果是否达到基本可信”，不指挥 Claude 如何写 React。

## 通用与轻量边界

Harness 只定义 `Screen / State / Action / Navigation / State Snapshot` 等通用字段，不包含购物车、收藏、订单等项目名称。项目自己的页面、按钮、数据和跳转只出现在各 Run 的 JSON 证据中。此次只新增一份 `state-snapshots.json` 并扩展现有事实、行为、Context 和 checkpoint 校验；不增加新阶段、审批系统、多 Agent 或自动 review 循环。

## 流程

```text
用户指定项目或范围
        ↓
事实发现：静态源码 + codebase-memory + 必要的 iOS 运行
        ↓
事实锁：Screen / State / Action / Navigation / Flow / Data / Asset + Critical Visual Set
        + iOS/Web 共用的 State Snapshot
        ↓
生成前依据：每屏事实切片 + 关键截图 OCR 文字框 / 主色 / 尺寸 / 原始 Assets
        ↓
Claude 自主完成首版 WebApp
        ↓
真实性检查 → 全量 Screen+State 基础覆盖 → 核心行为 → 关键视觉与差异分流
        ↓
最多两轮证据驱动精修 → AUTO_COMPLETE / NEEDS_REVISION → 用户查看 → USER_ACCEPTED
```

## 事实怎么来

| 来源 | 作用 |
| --- | --- |
| 静态扫描 | 找候选页面、声明和显式状态；不能单独判定完整业务 |
| codebase-memory | 从 App 入口追踪导航、调用和依赖，发现静态目录统计漏掉的目标 |
| iOS 运行 | 确认条件页面、空/有数据等源码无法可靠还原的状态 |
| Claude | 合并证据并实现 Web；不能自己创造源事实 |

每条重要事实记录 `fact / source / evidence / confidence`。每屏另有 `NAVIGATION` 事实，明确 `TAB_ROOT / NAV_PUSH / SHEET / FULL_SCREEN_COVER`、所属 Tab、TabBar 是否显示和进入/退出效果。核心交互使用 `ACTION` 事实记录前置条件、数据效果、导航效果和可见反馈。锁定后如发现新事实，必须用有历史记录的 revision，不能静默删页面。

`state-snapshots.json` 为关键状态固定同一用户、记录 ID、列表内容、地址、选中项和预期金额，并绑定 iOS Flow 与 Web seed/test。这样 VRT 比较的是同一个状态，而不是两个名字相同但数据不同的页面。

## 生成前怎么减少 Claude 猜测

`./harness context` 不会生成固定 UI 代码，也不会限制 React 架构。它只做两件事：

| 输出 | 作用 |
| --- | --- |
| `contexts/*.json` | 每个 Screen 只携带当前页面相关的源码事实、状态、依赖和资源；与事实锁哈希绑定，旧事实不能继续指导新修改 |
| `visual-grounding/*.json` | 对 Critical Visual Set 的 iOS 截图提取画布尺寸、主色及覆盖率、OCR 文字与位置、截图哈希和相关 Assets，供首版使用 |

OCR 使用本机 Tesseract；环境没有 OCR 时会明确标记 `UNAVAILABLE`，不会把 AI 猜测写成识别结果。截图仍只是布局/运行证据，不能复制为 Web 背景。

## 验收分层

| 范围 | 检查 |
| --- | --- |
| 所有 Screen+State | 路由可打开、页面非空、关键内容存在、图片加载、无严重 console/page error |
| 核心流程 | Playwright 真实点击、输入、跳转并断言结果；每个交互 step 引用锁定 ACTION 事实，不能从 Web 实现反推预期 |
| Critical Visual Set | 选择顶层导航、核心流程、数据密集、状态复杂或独特布局页面；状态型核心页面至少覆盖空和有数据；Maestro 与 Web 使用同一 State Snapshot 后做 Pixelmatch + SSIM |

每次自动检查必须启动当前工作区自己的独占 Web 服务并生成本 Run 的新截图，不能复用已占端口的旧服务或旧截图。桌面浏览器可有灰色外层画布，但页面、弹层和底部导航都必须保持在手机宽度内。

VRT 指标在 v0.x 仍是实验数据，不是永久验收阈值；当前临时分流值是整图 `changed_ratio ≥ 0.20`、`SSIM ≤ 0.60`，或任一局部网格变化率 `≥ 0.40`。局部指标防止大面积空白掩盖按钮、数据区或导航区差异。首版完成后执行 `checkpoint --stage first-pass`；每次精修后执行 `checkpoint --stage repair --evidence <本Run失败报告>`。没有失败证据或 Web 内容哈希未变化时，该轮不会被记录。最多两轮后交给用户判断。

## 防止假完成

页面或状态遗漏、占位事实、缺失页面呈现方式、核心动作没有源码后置条件、iOS/Web 状态身份不同、占位图片、测试数据、无来源资源、iOS 截图背景、隐藏 DOM、没有真实行为、陈旧服务/截图、固定元素越出手机壳、关键状态缺失、视觉报告缺失或明显差异被标记，都会阻止 `AUTO_COMPLETE`。

`AUTO_COMPLETE` 只说明自动证据齐全。用户打开链接后才可记录 `USER_ACCEPTED`。

本项目不再建设 G0～G8、审批系统、自动 Codex 循环或通用 Agent 平台。
