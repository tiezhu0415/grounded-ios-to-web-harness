# iOS→Web Harness 技术方案

## 目标

把任意 iOS App 迁移为一个完整、可操作、手机尺寸的 WebApp，并用真实 iOS 页面逐页检查还原度。

## 谁做什么

| 组件 | 职责 |
| --- | --- |
| Claude | 根据源码和 codebase-memory 理解当前 App，生成该 App 的页面状态、Maestro Flow、WebApp 和 Playwright 测试 |
| Maestro | 可重复点击真实 iOS App，进入每个页面并截图 |
| Playwright | 在 Web 中执行对应操作，验证行为并截图 |
| Pixelmatch + SSIM | 标出像素差异和整体结构差异 |
| Harness | 生成通用清单、执行工具、防止缺少证据却宣称完成 |

## 如何防止漏页面和状态

| 结果 | 找什么 |
| --- | --- |
| 源码扫描 | View/ViewController、导航、弹层和条件分支 |
| codebase-memory | 从 App 入口能到达的页面及页面关系 |
| Maestro | 实际能进入的页面和实际出现的状态 |

三份结果取并集后逐项对账：关系图发现但清单没有的页面必须补入；源码状态分支必须映射为视觉状态或说明其不可见；每个页面和必需状态必须由 Maestro 真正访问。它只增加一份机器清单，不增加用户审批步骤。

## 流程

```text
iOS 源码、导航和 Assets
          ↓
项目覆盖.json + visual-matrix.json
          ↓
codebase-memory 补齐导航关系和状态映射
          ↓
Claude 生成 Maestro Flow，iOS 逐页操作和截图
          ↓
reconcile 对账源码、关系图与真实访问
          ↓
WebApp 实现 + Playwright 对应状态截图
          ↓
逐页 Pixelmatch + SSIM
          ↓
差异最大页面最多精修两轮
          ↓
用户打开一个 WebApp 链接验收
```

## 通用性

Harness 不包含任何固定页面名、按钮名或业务提示词。`visual-matrix.json` 的默认状态来自源页面，Claude 再根据当前 App 增加空/有数据等必需状态。

## 不限制 Claude 的部分

Claude 仍可自由决定 React 架构、组件划分、CSS、状态管理、数据层和修复方法。Harness 只固定 iOS 事实、覆盖范围和验证证据。

## 完成条件

1. 每个源页面有 Web 实现、路由和行为测试；
2. 源码、codebase-memory 导航结果与 Maestro 实际访问三方对账通过；
3. 每个必需状态有独立 Maestro Flow、iOS 截图、Web 截图和唯一 Playwright 测试 ID；
4. 每个状态有 Pixelmatch + SSIM 报告；
5. 明显结构差异不得通过；
6. build、lint、Playwright 和手机外壳检查通过；
7. 最后由用户查看链接验收。

不再建设 G0～G8、审批记录、通用 Agent 平台或额外治理文档。
