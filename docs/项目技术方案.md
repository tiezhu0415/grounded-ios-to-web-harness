# iOS→Web Harness 技术方案

## 项目目标

把真实 iOS App 中由用户指定的功能忠实迁移为可运行、可验证的 Web 页面。

用户只参与两次：开始时指定功能，完成后打开链接查看结果。

## 整体架构

```text
源 iOS 项目
  ├─ codebase-memory：定位页面、子组件、依赖和 Assets
  ├─ SwiftUI/UIKit 源码与 Assets：确定布局、内容、资源、颜色和字体
  └─ 运行界面：固定真实数据、状态和动态行为
            ↓
       iOS→Web 组件映射
            ↓
       React WebApp 首版
            ↓
       同状态、同画布截图
            ↓
       Pixelmatch 主差异 + SSIM 辅助分数
            ↓
       最多两轮局部精修
            ↓
       Playwright 行为验证
            ↓
       WebApp 查看清单
```

## 执行流程

| 步骤 | 谁执行 | 产物 |
| --- | --- | --- |
| 用户指定项目和功能 | 用户 | 一句话任务 |
| 分析源码并运行 iOS | AI | 可见事实、组件/资源映射、iOS 证据 |
| 忠实实现 Web | AI | `webapps/<project-id>/` |
| 对比与精修 | AI | 每个映射状态的同画布截图、Pixelmatch 差异图、SSIM 分数，最多两轮 |
| 自动验证 | AI | Playwright 行为结果 |
| 查看最终结果 | 用户 | 继续、调整或停止 |

AI 开始工作的统一入口：

```bash
./harness capture --project <project-id> --feature <feature-id>
```

命令固定本次项目、功能和证据目录，并生成组件映射模板；AI 自动完成后续源码分析、Web 实现和测试，不增加人工审批。

中间不设置人工审批 Gate。视觉差异只指导 AI 精修，不设置自动通过线，也不阻塞用户。只有源 App 无法运行、需要敏感或付费服务、原生行为冲突或两轮后仍无法忠实还原时，AI 才询问用户。

## 忠实迁移原则

- 可见内容与功能、原 Assets/字体/颜色、页面层级与核心交互是不可改写的事实；
- AI 不得自行把多页面压成单页、把列表改成网格或增加新导航；
- codebase-memory-mcp 负责定位完整相关源码，AI 必须先形成逐组件映射再实现；
- iOS 运行用于固定本次可见数据、动态状态和交互，不得用 Preview 或虚构数据替换；
- Web 首版后必须为组件映射表中的每个状态生成相同画布差异图，优先修正差异最大的区域，最多两轮；
- 对比前还要确认数据和资源加载状态相同；一端图片加载失败、另一端成功时，差异图只能说明状态不同，不能当作还原度分数；
- Pixelmatch 负责主要像素差异并忽略常见抗锯齿噪声；SSIM 只辅助观察整体结构，不能掩盖小图标、文字或按钮缺失；
- Playwright 通过只代表行为可用，不等于忠实还原完成；视觉指标也不代表必须追求操作系统级 100% 像素一致。

## 工具分工

| 工具 | 用途 |
| --- | --- |
| Xcode / Simulator | 构建、运行并观察 iOS 功能 |
| codebase-memory-mcp | 查找模块、符号、调用和依赖 |
| Claude / Codex | 分析、实现或按用户要求审查 |
| React + TypeScript | 实现 WebApp |
| Playwright | 验证 Web 行为并生成截图 |
| Pillow | 裁剪、统一尺寸、生成对照拼图与重点区域 |
| Pixelmatch | 主要视觉差异检测，减少字体抗锯齿等渲染噪声 |
| SSIM | 输出整体结构相似度辅助分数，不单独判定完成 |
| Git | 记录可追溯输入与实现历史 |

## 文件组织

```text
xcode/<project-id>/                 源 iOS 项目
webapps/<project-id>/               对应 WebApp
docs/项目/<project-id>/项目蓝图.md  功能与源码地图
.runs/<project-id>/<run-id>/        单次组件映射与迁移证据
```

每次运行只保存最小过程数据：`scope.md`、`组件映射.md`、iOS/Web 证据、视觉差异结果和 `result.json`。

视觉比较依赖在仓库根目录安装一次：`npm install`。`./harness check --mode complete` 会确认“对比状态”表中的每个状态都有 Pixelmatch + SSIM 报告。
