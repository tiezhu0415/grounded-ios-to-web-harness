# 项目 Authority

> 版本：`2026-08-10.1-draft`
>
> 状态：`DRAFT — WAITING FOR USER APPROVAL`

## 1. 唯一目标

在 1～2 天内跑通一个真实的小型 iOS→Web 功能闭环，用实际结果判断这种 Harness 是否值得继续开发。

## 2. 当前只做

1. 固定并启动一个真实 iOS 项目；
2. 使用成熟工具生成全项目简明蓝图；
3. 由用户选择一个小功能；
4. 详细分析选中功能；
5. 使用 Spec Kit 制订最小计划；
6. 使用 Claude 实现一个 React Web 功能；
7. 使用 Playwright 验证，并由用户最终验收。

## 3. 当前不做

- 不自研 Swift analyzer、AST 或代码知识图；
- 不实现通用 Runner、复杂状态机和数据库；
- 不自动探索或点击所有 iOS 按钮；
- 不要求每阶段 Codex 审查；
- 不要求每阶段价值复盘；
- 不迁移整个 App；
- 不启动第二项目；
- 不增加没有真实需求的 Schema、Gate 和恢复机制。

## 4. 三个决定点

| 决定点 | 条件 | 决定者 |
| --- | --- | --- |
| 源项目可用 | commit 已记录，App 真实启动 | 执行者提供证据 |
| 迁移范围确认 | 蓝图可读，用户选择并确认一个功能 | 用户 |
| 最终验收 | Web 功能和测试结果可查看 | 用户 |

## 5. 角色

| 角色 | 职责 |
| --- | --- |
| 用户 | 选择功能、批准方向、最终验收 |
| Claude | 主执行者，维护计划、分析、实现和测试 |
| Codex | 用户按需触发的只读审查者；默认不参与每个步骤 |
| Harness | Skill、少量脚本、模板和证据目录的组合 |

## 6. 审查和循环限制

- Claude 自动修复同一问题最多两轮；
- Codex 只在用户要求、最终验收前或连续两轮修复失败时调用；
- 出现第三轮同类问题时必须停止并向用户报告；
- 聊天决定只有写入本文或用户文档后，才成为长期项目事实。

## 7. 批准后的第一步

用户批准本文后，Claude 按 `.planning/task_plan.md` 开始 Phase 1。批准前不得创建 WebApp 或宣称 Harness 已实现。
